Title: Support native IC-7300MK2 LAN control and audio

PiRO can connect directly to an IC-7300MK2 over Ethernet for rig control,
receive/transmit PCM, scope and typed CW, without USB/ALSA or another radio
application. USB remains the default connection.

Integrated upstream StevPem/piro main at da2d962, retaining its Origin checks,
heartbeat/PTT ownership, queue ordering/stale-ACK protection, backpressure,
CW keyline/paddle support, JS8, STT and DeepCW worker. Build/cache is v137.

LAN initialization uses the authenticated session's advertised CI-V address
then independently verifies the MK2 model, so custom addresses remain usable.
Reconnect repairs cached scope status. LAN radio loss cancels paddle/JS8 work;
JS8 waits for paced audio to drain before unkeying, and failed LAN watchdog
release preserves unknown PTT state rather than falsely confirming receive.
USB keyline configuration and upstream queue limits/order are preserved.
The LAN suite uses a wrapper compatible with upstream's CI test runner.

Hardware evidence predates integration:
- Physical IC-7300MK2 receive/control sweep: frequency, six modes, filters,
  DATA, receive controls, meters, 475-point scope and three spans.
- Operator-authorized 5 W dummy-load voice/DATA PCM, typed CW completion,
  active CW abort, PTT release and readback of restored active settings.
- Candidate discovery verified on the radio without an explicit address.
- Clean service restart recovered receive audio and scope.
See docs/icom-lan-hardware-validation.md for observations and limits.

Integrated validation: TEST_RETRIES=0 npm run test:ci passed 65/65 file
groups (68 LAN subtests) in 338 seconds. Syntax and diff checks passed.
The hardware report records the exact scope and remaining limits.
No new npm dependencies. No credentials are included in this change.
The Pi now runs integrated build v137, including the RADE hotfix and shared
radio manager. A receive-only live disconnect/reconnect test released all
three radio UDP sockets, restored audio and scope, retained tuning/mode, and
kept the same process with zero restarts. No RF was sent for that test.

Limits:
No independent RF power/spectrum or digital decoder measurement, firmware
record, two-hour soak, packet-loss/VPN test, or physical network/radio failure
while transmitting. Repeat hardware checks after deploying the integrated
build. The manual mode sweep restores the originally active mode/filter;
other modes' stored filter preferences are not restored.

This is a preparation draft, not a published PR.


RADE crash follow-up:
Contains asynchronous child pipe failures and stops pipelines before notifying
callers. Failed TX clears buffered playback and requests PTT off while keeping
raw mic muted until confirmed release. Verified by 91 pipeline/bridge checks
and a live missing-codec RX smoke check: same PID, zero restarts, audio and
scope recovered after disabling FreeDV. Native RADE tools have subsequently
been built and installed; native and actual PiRO RX software round trips
passed without RF, and the V1 text tests passed6/6. Whisper STT is still optional
and unconfigured. Installation evidence is recorded in the hardware report.


Shared radio connection manager:
Top-right radio-status dropdown beside the browser Connected/count indicator
can release and reopen the configured native LAN session without stopping
PiRO. All browsers share status. Manual disconnect stops retries/transmit work,
restores reachable settings and releases streams; reconnect starts fresh audio
and scope. UI polls/controls pause while offline, with keyboard and touch
access. Lifecycle regressions cover rollback, delayed ACKs, retry cancellation,
multiple callers, repeated reopen, audio recovery and queued TX discard.


Mode-aware reconnect follow-up:
The physical MK2 rejected CW-stop in USB. Startup now keeps the selected mode,
releases PTT, stops the keyer only in CW modes, and verifies receive state.
All96 LAN subtests and the CI-V driver/version checks passed. Physical USB/FIL2
Disconnect/Connect retained14.083750MHz and restored audio/scope with no
process restart or RF. The radio is left connected.
